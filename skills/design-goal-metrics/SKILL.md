# Design Goal Metrics

This is a generic capability skill, not an employee or named worker. Do not invent a person or employee identity for it.

1. Read `GOAL.md` after the required `USER.md → BUSINESS.md → GOAL.md` startup sequence. If the goal is empty, invoke `$onboard-cofounder`.
2. Restate the outcome, baseline, target, current value, deadline, gap, and evidence source.
3. Use [metric ladder](references/metric-ladder.md) to choose:
   - exactly one primary outcome metric;
   - two to five leading indicators;
   - one to three controllable input metrics;
   - one to three guardrails.
4. Define every metric with the fields and review rules in [scorecard and review](references/scorecard-and-review.md).
5. Mark missing baselines and targets as unknown. Label provisional targets as hypotheses.
6. Reject metrics that do not change a decision, duplicate another measure, or lack a credible source.
7. Present the proposed system for confirmation. Persist confirmed values to the declared metric paths in `GOAL.md`; never silently redefine the primary outcome or a guardrail.
8. Create a page from `second-brain/templates/metric.md` only when a metric needs durable collection details or observation history.
